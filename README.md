# দোকান-টেমপ্লেট (Next.js + Supabase)

বাংলাদেশের ক্যাশ-অন-ডেলিভারি দোকানের জন্য তৈরি। WordPress/WooCommerce-এর
বদলে — দ্রুত, নিরাপদ, আর প্লাগইনের উপর নির্ভরতা নেই।

## নতুন ক্লায়েন্ট বসাতে যা যা লাগে

পুরো ফোল্ডারটা কপি করুন, তারপর শুধু এই চারটা জিনিস:

| কী | কোথায় |
|---|---|
| ১. ব্র্যান্ড, রং, ক্যাটাগরি, লেখা | `src/config/site.ts` — **একটিমাত্র ফাইল** |
| ২. লোগো | `public/img/logo.webp` ও `logo-sm.webp` |
| ৩. প্রোডাক্ট | `supabase/seed.sql` |
| ৪. কি ও টোকেন | `.env.local` (`.env.example` দেখুন) |

কোডের আর কোথাও ব্র্যান্ডের নাম, রং, ফোন নম্বর বা দোকান-নির্দিষ্ট বাংলা
লেখা বসানো নেই। রং বদলালে `tailwind.config.ts` নিজে থেকেই তুলে নেয়।

## ডাটাবেস (Supabase)

SQL Editor-এ এই ক্রমে চালান:

1. `supabase/schema.sql` — টেবিল, RLS, ভিউ (সব ক্লায়েন্টে এক)
2. `supabase/stock-functions.sql` — স্টক রিজার্ভ/ফেরতের ফাংশন
3. `supabase/seed.sql` — এই দোকানের প্রোডাক্ট ও সেটিংস

`supabase/migrations/` ফোল্ডারটা **নতুন সাইটে লাগে না** — `schema.sql`-এ
সবই আছে। ওগুলো শুধু পুরনো কোনো ইনস্টল আপগ্রেড করার জন্য।

তারপর অ্যাডমিন অ্যাকাউন্ট:

- Authentication → Users → **Add user**
  ইমেইল `<ইউজারনেম>@<site.ts-এর adminEmailDomain>`, "Auto Confirm User" টিক
- তারপর SQL Editor-এ:
  ```sql
  insert into admin_users (id, email, role)
  select id, email, 'owner' from auth.users where email = '...';
  ```

Storage-এ `products` নামে একটা পাবলিক বাকেট বানান — অ্যাডমিন প্যানেল থেকে
আপলোড করা ছবি ওখানে যায়।

## যা ভেতরে আছে

- **দোকান** — হোম, শপ, প্রোডাক্ট পেইজ, কার্ট, চেকআউট (ক্যাশ অন ডেলিভারি)
- **অ্যাডমিন প্যানেল** — প্রোডাক্ট, স্টক, অর্ডার, ছবি আপলোড, CAPI ইভেন্ট লগ
- **Meta Pixel + Conversions API** — একই `event_id` দিয়ে ডিডুপ্লিকেশন,
  `fbp`/`fbc` সংরক্ষণ, `fbclid` থেকে `fbc` উদ্ধার
- **স্টিডফাস্ট কুরিয়ার** — অর্ডার পাঠানো ও ওয়েবহুকে স্ট্যাটাস আপডেট
- **স্টক** — এক স্টেটমেন্টে রিজার্ভ, তাই একসাথে দুই অর্ডারেও ওভারসেল হয় না

## ভ্যারিয়েন্ট — সাইজ ও রঙ

`product_variants`-এর প্রতিটি সারি একটা *জোড়া*: সাইজ + রঙ। স্টক গোনা হয়
ওই জোড়া ধরে, তাই লালের ৩৬ শেষ হলে কালোর ৩৬ বিক্রি হতে থাকে।

- **সাইজ নেই** → একটাই সারি, `opt_key = 'one'` — সাইজ বাছার ঘর দেখায় না
- **রঙ নেই** → `color_key = ''` — রঙ বাছার ঘর দেখায় না
- **দুটোই নেই** → গহনা বা কসমেটিকসের মতো, কোনো বাছাবাছি নেই

অ্যাডমিন প্যানেলে সাইজ আর রঙ আলাদা তালিকায় দেওয়া হয়; সার্ভার নিজেই সব
জোড়া বানিয়ে নেয় (`src/lib/syncVariants.ts`)। অক্ষ দুটোর নাম
`site.ts → words.optionAxis` ও `words.colorAxis`-এ বদলানো যায়, আর রঙের
প্রস্তাবিত তালিকা `site.ts → colorSuggestions`-এ।

⚠️ যে পণ্যে ইতিমধ্যে স্টক আছে, তাতে **প্রথমবার রঙ যোগ করলে ঘরগুলো নতুন
করে তৈরি হয় আর স্টক ০ হয়ে যায়** — পুরনো সংখ্যাটা কোন রঙের ছিল জানার
উপায় নেই। অ্যাডমিন প্যানেল সেভের আগে সতর্ক করে।

## ল্যান্ডিং পেইজ (CartFlows-এর বদলে)

এক পেইজ = এক পণ্য + তার নিজস্ব অফার (১টা ৳৪৩০, ৩টা ৳৯৯০)। ডাটা থাকে
`landing_pages` টেবিলে, অ্যাডমিন থেকে বদলানো যায় (**অ্যাডমিন → ল্যান্ডিং পেইজ**)।

- ঠিকানা `/product/<slug>/` — পুরনো WordPress/CartFlows-এর মতোই, শেষে
  স্ল্যাশসহ। চালু এডের লিংক তাই বদলাতে হয় না। স্ল্যাশ থাকলে রিডাইরেক্ট
  হয় না, একই পাতা দেখায় (`src/middleware.ts`)।
- `/product/FA-01` ধরনের (কোড) ঠিকানা দোকানের প্রোডাক্ট পেইজ; বাকি সব
  `/product/<কিছু>` ল্যান্ডিং পেইজের রুটে যায় (`src/app/lp/[slug]`)।
- দাম সার্ভারে হিসাব হয় পেইজের অফার থেকে — ব্রাউজার শুধু "কয়টা" পাঠায়।
- অর্ডারের পরে `thankyou_slug`-এর পাতায় যায় (যেমন `/product/thank-you-3/`)
  — পুরনো সাইটের মতোই, যাতে URL-ভিত্তিক কাস্টম কনভার্শন না ভাঙে।
- পিক্সেল: ViewContent (পাতা খুললে), InitiateCheckout (ফর্মে হাত দিলে),
  Purchase (সার্ভার + ব্রাউজার, একই event_id)।
- পেইজের অংশ (`blocks`): heading · text · image · gallery · video · list ·
  features · compare · cta। ছবি `public/lp-img/`-এ বা Supabase Storage-এ।
- পুরনো লিংকের রিডাইরেক্ট: `src/config/redirects.mjs`।

পুরনো ইনস্টলে চালান: `supabase/migrations/2026-10-03-landing-pages.sql`।

## প্রোডাক্ট ভিডিও

অ্যাডমিন প্যানেলে ইউটিউব লিংক বসালে প্রোডাক্ট পেইজে ছবির নিচে ভিডিও আসে।
iframe আগে থেকে লোড হয় না — শুধু থাম্বনেইল (~২০ KB) আর প্লে বোতাম, ক্লিক
করলে তবেই আসল প্লেয়ার। watch / youtu.be / shorts / embed / live — সব
চেহারার লিংকই চেনে (`src/lib/youtube.ts`)।

## ভাঙলে কী হয়

- `(shop)/error.tsx` ও `global-error.tsx` — বাংলায় বার্তা, "আবার চেষ্টা
  করুন" বোতাম। Next-এর ইংরেজি "Application error" পাতা আর আসে না।
- পুরনো বিল্ডের জাভাস্ক্রিপ্ট ফাইল না পেলে পাতা নিজে থেকেই **একবার**
  রিফ্রেশ হয় (`src/lib/stale.ts`) — লুপ হয় না।
- `next.config.mjs → expireTime: 3600` — CDN যেন এক বছরের পুরনো HTML
  না দেয় (Next-এর ডিফল্ট এক বছর)।
- `Housekeeping.tsx` — পুরনো WordPress সাইটের রেখে যাওয়া service worker
  ও ক্যাশ কাস্টমারের ব্রাউজার থেকে একবার মুছে দেয়। আক্রান্ত সাইট
  রিপ্লেস করলে এটা জরুরি: সার্ভার পরিষ্কার করলেও ওটা ব্রাউজারে থাকে।
- কার্ট localStorage থেকে পড়ার সময় যাচাই করা হয় — নষ্ট মান থাকলে পুরো
  সাইট ভেঙে পড়ে না।

## হোস্টিং

Hostinger Cloud → Web Apps → GitHub থেকে ডিপ্লয়। পুশ করলেই নিজে থেকে
বিল্ড হয়। এনভায়রনমেন্ট ভেরিয়েবলগুলো hPanel-এ বসাতে হয় (`.env.example`
দেখুন); ওখানে কিছু বদলালে নিজে থেকেই আবার ডিপ্লয় হয়।

⚠️ `SUPABASE_SERVICE_ROLE_KEY` কখনো `NEXT_PUBLIC_` দিয়ে শুরু করবেন না —
তাহলে কি-টা ব্রাউজারে চলে যায় আর যে কেউ পুরো ডাটাবেস পড়তে-লিখতে পারে।
